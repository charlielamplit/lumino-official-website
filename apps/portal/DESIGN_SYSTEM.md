# Lumino CBAM Portal · UI Contract

> 适用范围：`portal/` 登录页与登录后客户、专家、运营、商务页面。
> 设计语气：清晰、可信、克制严谨；像一名会把复杂事情讲清楚的合规同事。

## 1. 界面原则

1. 客户先看到业务任务，专业字段逐步展开。
2. 每个页面只有一个明确的主操作，其余使用次操作或文字操作。
3. 白色与浅中性表面是主体；绿色只用于主操作和当前状态，暖黄只用于待处理、不确定或金额差额强调。
4. 卡片只用于存在明确对象边界的内容，不为装饰而套卡片。
5. 动态结果必须告知用户；正式状态不只靠颜色表达。
6. 桌面业务系统采用紧凑信息密度：36–40px 控件、明确分组、减少装饰性留白；触控设备仍保持至少 44px 目标。

## 2. Token 层级

`styles.css` 的 `:root` 直接继承 `Lumino 官网.dc.html` 与 `Lumino 设计系统.dc.html` 的公开站 token，分为四层：

| 层级 | 代表 Token | 使用方式 |
|---|---|---|
| 品牌原语 | `--forest` `--green` `--yellow` `--mint` | 不直接表达业务状态 |
| 语义颜色 | `--surface-*` `--text-*` `--status-*` | 组件优先使用本层 |
| 尺寸与节奏 | `--space-*` `--control-*` `--radius-*` | 禁止为新组件随意新增 13px/17px 等数值 |
| 交互 | `--duration-fast` `--ease-out` `--focus-ring` | 所有焦点和快速反馈共用 |

新增 token 前先检查它是否有跨 3 个组件的复用价值。

## 3. 字体

- Display：Archivo + Noto Sans SC，用于页面级标题。
- Body：Instrument Sans + Noto Sans SC，用于导航、表单、表格和说明。
- Label：IBM Plex Mono，只用于短小的英文 eyebrow、编号、记录代码和金额数字。
- 应用内页标题使用固定尺寸，不使用大幅流式字号；登录叙事区可使用 `clamp()`。

### 官网一致性基线

- Logo 使用黑色字标、绿色下部叠印与横向切线，登录前后不变体。
- 客户页面圆角为 3–6px，不使用大圆角代替信息层级。
- 重要摘要优先参照官网 Communication Form：白底、细边框、黑色顶部分隔，不大面积填满深绿。
- 每页最多使用一个深绿品牌主区，例如服务订单、交付或结果摘要；其余区域回到白底细边框，不连续堆叠深绿卡片。
- 阴影仅用于浮层、Toast 和移动导航；普通卡片通过边框建立层级。
- 登录页复用官网 76px 顶栏、1200px 版心语汇、浅绿至白的主画布与斜线背景，不另起一套深色登录品牌。
- Portal 顶栏高度同步为 76px，主内容最大宽度为 1200px；侧栏属于应用导航，不改变内容版心的官网节奏。

## 4. 基础组件

### Page Header

所有一级页面通过 `pageHeader(eyebrow, title, aside)` 生成：

- 左侧：短 eyebrow + 唯一 `h1`；
- 右侧：只能是主操作、当前状态或角色视图说明；
- 不在页头重复主体页面已经显示的指标。

### Button

| 变体 | 类名 | 场景 |
|---|---|---|
| Primary | `.button.button--primary` | 创建、上传、确认、邀请 |
| Secondary | `.button.button--secondary` | 编辑、取消、预览、非破坏性备选操作 |
| Text | `.text-button` | 页内导航、展开解释；桌面紧凑，触控设备至少 44px |
| Icon | `.icon-button` / `.round-action` | 必须有可理解的 `aria-label` |

`.action.primary-action` / `.action.secondary-action` 是已有原型的兼容别名；新建页面只使用 `.button` 命名。

### Status

- 年度/项目阶段：`statusChip(label, tone)` / `.status-chip`。
- 行级处理状态：`.record-state`。
- `warn` 只表达需注意，不与错误或拒绝混用。
- 所有状态必须同时包含文字，不能只显示彩色点。

### Panel

- `.panel` 只定义边界与表面；
- `.panel-head` 是标准容器标题；
- `.section-heading` 仅用于复合对象内部区域，不作为新的页面标题变体；
- 禁止纯装饰性卡片嵌套。

## 5. 可访问性契约

- 导航当前项使用 `aria-current="page"`；
- 年度路线当前步使用 `aria-current="step"`；
- 可切换对象使用 `aria-pressed`；
- 桌面按钮和选择控件为 36–40px；在窄屏与触控上下文中最小高度 44px；
- 页面动态反馈通过 `#toast[role=status][aria-live=polite]` 播报；
- 不以颜色作为唯一状态线索；
- 强制颜色模式下，当前导航、步骤和产品保留轮廓。

## 6. 响应式契约

- `>1120px`：桌面多栏，侧边导航常驻。
- `821–1120px`：平板/窄屏，次要上下文换行。
- `561–820px`：单栏主体，导航抽屉。
- `320–560px`：触控优先，主体文字不小于 14px，核心功能不隐藏。
- 表格可在自身容器内滚动，不允许撬开整页宽度。

## 7. 新页面检查清单

- [ ] 使用 `pageHeader()` 且只有一个 `h1`
- [ ] 页面最多一个主操作
- [ ] 新样式使用语义 token，没有新的硬编码品牌色
- [ ] 当前项有 ARIA 状态
- [ ] 390px 无整页横向溢出
- [ ] 键盘焦点可见
- [ ] 动态操作有成功/失败反馈
- [ ] `prefers-reduced-motion` 下不依赖动画理解状态

## 8. 角色与对象上下文

- 客户角色必须明确区分企业管理员、项目协调人、数据贡献者和内部审批人；不能以单一 `customer` 身份承载全部动作。
- 专家必须区分制备专家与独立复核专家，界面不得向制备人展示自己制备内容的最终批准动作。
- 运营的跨客户页面使用服务订单、项目和 SLA 上下文，不显示单一年度选择器。
- 企业管理员的组织与订单页面是跨年度视图；项目协调人、数据贡献者和审批人保留明确的年度上下文。
- Lumino 服务订单与客户出口订单必须使用不同名称、编号和状态，避免用户误解。
- 锁定年度隐藏所有原位写入动作，并引导用户创建 Amendment Revision。
- 每个专家案件页面显示服务订单、工作包、授权范围、授权期限和不可见数据边界。

## 9. 产品主档与年度范围

- 产品主档属于企业，是跨年度的长期对象；不得在创建时绑定为某一年度专属产品。
- 年度项目通过“纳入年度”引用产品主档，同一产品可同时进入多个开放年度。
- 已锁定年度不能直接新增或移除产品引用，只能通过 Amendment Revision 处理。
- 工厂、工艺、前体来源属于产品下的生产配置；同一产品允许多个配置分别核算再汇总。
- 产品停用只影响未来年度候选，不删除历史年度快照、证据或计算血缘。

## 10. 项目协调人连续任务契约

协调人的主路径固定为“回答业务问题 → 核对产品配置 → 收集并确认证据 → 选择数据路径 → 检查交付准备度”。

- 每个状态变更必须同时给出结果反馈和唯一的下一步入口；Toast 只确认结果，不承担导航。
- `.next-action` 用于跨页面推进，必须写明当前任务位置、下一步目的和完成后产生的价值。
- 年度路线图的每个节点都可以进入对应工作或查看要求，不能使用无动作的按钮。
- 上传与解析分离：上传后必须经过 Agent 提取结果确认，才能进入正式事实建议和新计算版本。
- 缺口处理必须先选择路径、显示影响，再由用户确认；不能单击后直接关闭 Finding。
- 主页任务列表的每一项都必须可到达实际处理页面；完成后应能回到主路径继续。
- 空状态和等待状态必须说明“在等谁、等待什么、用户现在还能做什么”。

## 11. 操作指南契约

- 侧栏使用“操作指南”而不是内部项目术语“年度路线图”；
- 页面首先回答“整个平台怎么用”，再展开当前年度的 7 个步骤；
- 免费试算是门户外的可选入口，不得成为创建年度项目的前置条件；已有账号直接登录并启动或进入年度项目；
- 全局流程为：启动年度项目 → 确认范围与监测方法 → 按季度收集、核算并反馈进口商 → 年度报告、核查与申报支持；
- 页首始终显示“你现在在这里”与唯一的“继续当前工作”主操作；
- 每个年度步骤必须同时显示通俗任务、责任人、状态和输出物；
- 已完成步骤可返回查看记录，未开始步骤可查看要求，当前步骤直接进入实际处理页；
- “谁负责什么”固定区分客户及同事、Lumino Agent 和 Lumino 专家，避免用户把所有工作都理解为自己填表。

## 12. 季度与年度双周期契约

- 顶栏同时保留“年度项目”和“当前季度数据包”上下文；季度切换不得改变年度主档、监测计划或年度报告版本。
- 季度层管理 Q1–Q4 的产量、发运、能源、前体、证据、计算版本、成本估算和进口商 Communication Package。
- 年度层管理监测计划/监测报告、年度排放报告、年度核查、年度交付和封存；季度数据逐期累积进入年度数据集。
- 2026 年证书价格按季度管理；Q1 €75.36、Q2 €75.28、Q3 €82.32，Q4 待发布。从 2027 年起按周平均价格管理，计算版本必须保存实际采用的价格期间和来源。
- “季度数据包/进口商反馈”不得写成正式阶段的“季度 CBAM 法定申报”；2026 年起正式阶段的 CBAM declaration 为年度申报。
- 产品主档与年度、季度解耦。产品可以先创建，CN Code 可以为空或保留多个候选；最终确认必须留下关务/专家确认人与版本记录。
- 一个产品可以维护多个 CN Code 和多个生产配置；年度项目再选择当年适用的产品、编码与配置组合。

价格和频率依据：欧盟委员会 [CBAM certificate prices](https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/price-cbam-certificates_en) 与 [CBAM definitive regime](https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/cbam-definitive-regime_en)，核对日期 2026-10-10。

## 13. 顶栏项目上下文契约

- 顶栏中的年度和季度是“当前工作上下文”，不是企业、产品或设施的归属字段。
- 年度选择器在项目协调人与企业管理员进入年度执行空间时出现；企业管理员查看企业主档、成员权限等跨年度页面时弱化该上下文。运营项目组合、专家队列和商务视图不展示容易误导的单一年度上下文。
- 年度与季度必须作为一个紧凑的 `.project-period` 组件出现，并清楚标注“年度项目 / 季度数据包”；禁止使用大型强调色块抢占页面主操作层级。
- 切换年度会整体切换年度范围、版本和状态；切换季度只切换产量、能源、发运、前体和季度 Communication Package。

## 14. 年度继承契约

- 企业法定主体、设施、产品和 CN Code 候选引用创建年度时有效的主档版本，作为待确认结构。
- 工艺、供应商、职责和数据源映射可以复制为新年度草稿，但必须经 Agent 变化确认。
- 监测方法章节可以复制为新修订草稿，但必须经年度专业复核。
- 产量、能耗、采购、发运、供应商排放数据、默认值、证书价格、计算结果、批准状态、报告、核查结论和 Findings 一律不跨年度复制。
- 已锁定年度保持不可变快照；后续主档变化不得回写历史，必要时创建 Amendment Revision。

## 15. Drawer 交互契约

- 新增、编辑、上传、查看详情、审批和角色动作统一使用右侧 Drawer，避免按钮只显示 Toast 或跳到没有上下文的空页面。
- Drawer 标准宽度 440–560px；页头显示对象类型和标题，主体承载表单或详情，底部只保留取消/关闭与一个主操作。
- 上传必须呈现材料类型、设施、期间、文件和说明；新增必须呈现最小必填字段与保存后的下一步。
- 专家、复核、运营和商务动作必须显示当前角色、对象、权限范围、处理说明和审计记录提示。
- 关闭方式包括关闭按钮、背景层和 Escape；关闭后焦点返回触发按钮。
- Toast 只确认提交结果，不能替代 Drawer 中的表单、影响说明或详情内容。

## 16. 对象状态组件

年度阶段是由子对象聚合的只读结果，不是所有工作的共同状态。页面应组合使用以下共享模式：

| 模式 | 实现 | 用途 |
|---|---|---|
| 对象上下文条 | `objectContext(items)` / `.object-context` | 显示企业、年度、季度、设施、进口商、订单或授权范围 |
| 状态卡 | `workflowCard(id, flow)` / `.workflow-card` | 显示对象粒度、当前状态、进度与唯一下一步 |
| 状态标签 | `workflowStateLabel()` + `statusChip()` | 将内部枚举翻译为用户语言 |
| 状态详情 | `workflow-detail` Drawer / `.state-sequence` | 展示正常迁移、责任与审计控制 |
| 责任说明 | `.responsibility-notice` | 区分出口商、Lumino、核查员和欧盟申报人责任 |

### 16.1 状态命名规则

- UI 显示用户语言，例如“收集中”“已分享 · 待回执”；详情中保留枚举代码以便开发对照。
- `SHARED` 与 `ACKNOWLEDGED` 必须分开；没有对方回执不能显示“已接收”。
- “年度交付完成”不等于“欧盟申报人已完成法定申报”。只有外部凭据可以形成申报回执记录。
- 失败、拒绝、撤回、到期、被替代和无权限不是空白页，必须显示原因和恢复动作。

### 16.2 角色投影

同一对象只保存一份状态，角色页面仅做字段和动作投影：

- 客户：业务事实、缺口、成本影响和下一步；
- 专家/复核：证据血缘、规则版本、计算与报告修订；
- 运营：订单、SLA、工作包、交接与阻塞摘要；
- 商务：报价、合同、交接和获授权的里程碑摘要；
- 进口商/核查员/供应商：仅限被分享、被核查或被请求的对象范围；
- 平台支持/管理员：治理和运行元数据，默认不读取客户业务内容。

## 17. 首次使用与恢复性

- 已有账号可以直接登录开始项目；免费试算永远是可选入口。
- `.onboarding-guide` 只教“回答事实 → 核对产品与工厂 → 上传季度材料”，可跳过，并可在“操作指南”重开。
- 离线、失败、超限、无权限和过期状态必须保留用户输入，说明原因并给出重试、转交或申请权限入口。
- 提交按钮在处理中禁用并显示动词状态，防止重复创建；完成反馈必须说明发生了什么和下一步在哪里。
- 长文本允许换行，关键标识可省略显示但必须保留完整 `title` 或详情入口。

## 18. 可执行工作流契约

- 页面状态必须来自 `domain/workflow-engine.js` 中的对象，不得另维护一份仅供显示的当前状态。
- 状态卡必须显示对象 ID、修订号和负责人；Drawer 必须显示最近审计事件与允许的下一步。
- 用户操作不能直接改显示文案；必须执行合法迁移，再根据返回的对象重新渲染。
- 关键状态不允许“一键快进”：已接收需回执，已锁定需快照，Finding 关闭需解决依据与正确角色。
- 事实变化必须让依赖该事实的当前计算版本进入 `STALE`，新 Run 使用新 ID，不覆盖旧 Run。
- 年度标签为派生值，不得反向改写季度包、报告、核查或 Finding。
- 原型刷新后必须恢复工作流与用户草稿；正式系统改为服务端权威存储。

业务层完整契约见 `platform/03_Agent与数据模型/Lumino_CBAM_可执行状态机与审计契约_v1.md`。

## 19. 客户主路径与权限投影

- 客户侧只使用一套五阶段主路径：年度范围 → 年度监测计划 → Q1–Q4 数据循环 → 年度排放报告 → 核查与交付。
- 不得在同一页并列多套流程编号；技术对象状态只在详情、审计和治理界面出现。
- 工作台只有一个主操作，必须同时说明前置工作、当前动作和后续自动流向。
- 已有项目不得重新从“新增产品”开始；系统应根据对象完整度和阻塞项选择下一步。
- 企业管理员继承全部客户业务目录和企业治理能力；进入年度项目不强制切换为其他角色。
- 项目协调人与企业管理员共用业务信息架构，权限只决定动作可用性，不改变流程语言。

## 20. 三年度演示状态契约

- 2025 是完整封存年度：Q1–Q4、年度排放报告、核查、交付和回执均完成，只读查看；更正创建 Amendment。
- 2026 是当前执行年度：Q1、Q2 已完成，Q3 数据采集中，Q4 未开始；默认进入 Q3 唯一下一步。
- 2027 是待开始年度：可以确认范围、产品/设施变化和监测方法，但不得显示已经产生季度数据或计算结果。
- 工作台、全年流程、季度数据、计算结果和报告交付页面必须使用同一年度配置，不得各自硬编码阶段或百分比。
- 三个年度页面保持相同栅格、边界、标题和状态组件；内容差异通过状态、下一步和对象版本表达，不为每个年度另造页面风格。
