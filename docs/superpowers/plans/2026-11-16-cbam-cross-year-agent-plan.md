# CBAM 跨年度项目、并行收资与 Agent 边界实施 Plan

关联 Issue：[#71](https://github.com/charlielamplit/lumino-official-website/issues/71)

## 目标

让 Portal 符合真实 CBAM 项目：服务年度不等于自然年关闭时间；2026 申报年度可以持续到 2027 年一季度或更晚，完成全年关账、材料包、核查、Finding 整改、重算和修订交付后才封存。监测计划、年度主档确认与数据采集并行推进；Agent 只在年度项目进入收资后启用，并始终绑定年度项目和业务对象，而不是页面名称。

## 已确认业务模型

```text
合同签署
  → 系统服务授权
  → 创建年度项目并启动收资
     ├─ 产品 / CN Code / 设施年度确认
     ├─ 监测计划制备、复核与修订
     └─ 数据与证据采集
  → 数据关账与受控计算
  → 年度材料包与报告
  → 核查、Finding 整改与重算
  → 修订交付与年度封存
```

### 时间规则

- `serviceYear` 表示申报数据归属年度，不表示项目必须在 12 月 31 日结束。
- 项目另有 `targetClosePeriod`、当前工作阶段和实际封存时间。
- 2026 年度项目目标在 2027 Q1 完成；遇到核查 Finding、补证或重算时可以顺延。
- 年度切换不会自动关闭仍在核查或整改中的上一年度项目；同一企业可以同时存在 2026 收尾与 2027 收资。

### 并行与门禁规则

- 年度项目创建后，产品范围确认、监测计划和首轮材料采集可以并行。
- 监测计划不是上传材料的前置门禁；数据发现可以反向触发监测计划修订。
- 预估计算可以使用明确标注的未齐数据和方法草稿。
- 正式计算、受控报告和对外交付必须引用已确认年度范围、明确版本的监测方法和冻结的数据快照。
- 核查 Finding 可以让报告与计算回到整改 / 重算状态，但不得覆盖原有受控版本。

### Recurrent 年度规则

- 产品、CN Code、设施、路线和监测计划引用上一年度受控版本，再确认变化。
- 新增、停用、编码依据变化、生产路线变化和数据源变化形成差异；不要求客户重新录入全部信息。
- 产量、能耗、发运、计算结果、报告与核查结论不跨年度复制。

## Agent 启动与边界

- 服务启动授权页不展示 Agent；授权是系统治理，不是 Agent 工作。
- 年度项目向导未完成前不展示 Agent。
- 完成“创建年度项目并启动收资”后启用 Agent。
- Agent 上下文必须包含 `annualProjectId + serviceYear + workstream + objectRef`。
- 页面 ID 只用于展示，不再作为 Agent 判断业务上下文的唯一依据。
- Agent 可收集、提取、整理、检查缺项、计算和起草输出；具名范围确认、方法批准、复核和正式交付仍由人完成。

## 第一版界面调整

### 1. 年度项目页

- 移除“年度基础 4 / 4”线性进度条。
- 右上角状态改为可展开的项目生命周期，支持鼠标悬停、键盘聚焦和点击 / 触控。
- 明确展示服务年度、当前工作、目标封存期和下一里程碑。
- 增加跨年度说明：2026 项目在 2027 Q1 完成年度报告、核查和整改后封存，Finding 可能导致顺延。
- 产品范围与监测计划保持并列；文案明确两者与数据采集同步维护。

### 2. 新年度项目已创建状态

- 不再把范围、角色、监测计划渲染为线性四步。
- 改为“年度主档确认 / 监测方法 / 首轮材料”三条并行工作流。
- 创建项目的最终动作明确为“创建项目并启动收资”，此后 Agent 可用。

### 3. Agent

- `service-start` 和未完成年度项目向导时隐藏顶栏与页面 Agent 入口。
- `annual-project`、`data-calculation` 及其内部标签使用新的上下文映射。
- “材料与数据”映射收资 playbook；“计算结果 / 成本情景”映射计算 playbook。
- 产品命名统一为“产品与设施”。

### 4. 全年流程

- 保留跨年日期：年度报告发生在下一年 1–2 月，核查与整改发生在下一年 3 月起。
- 状态语言区分“申报年度”“当前工作阶段”和“是否封存”。
- 核查与 Finding 整改作为可回退、可重算的真实阶段，不表达为一次通过。

## 第一版暂不扩展

- 不在本轮构建完整多年度并行项目切换器。
- 不在本轮实现真实文件上传、模型调用或外部核查员协作后端。
- 不把所有历史年度数据迁移为新 Schema；先在原型视图和 Agent 边界中验证模型。

## 验证

- 状态与文案测试：Agent 启用边界、五项导航、跨年阶段、旧 route 兼容。
- 黄金路径测试：年度项目创建后收资与监测计划可并行，正式计算门禁保持。
- 浏览器检查：2027 服务启动无 Agent；向导无 Agent；创建年度项目后 Agent 出现；2026 年度页无线性基础进度；状态弹层可键盘与触控访问。
- 视口：390 / 768 / 1440；检查控制台错误和横向溢出。

## 完成定义

- 计划与代码一致，页面不再暗示项目必须在服务年度内结束。
- 监测计划与数据采集不再被表达成绝对先后关系。
- Agent 在项目收资开始前不可用，开始后绑定年度项目上下文。
- 2026 年度项目明确展示 2027 Q1 的报告、核查、整改和封存目标。
- 自动化测试通过，浏览器证据更新。

## 实施状态（2026-11-16）

第一版原型调整已完成：

- 年度项目页移除了“年度基础 4 / 4”线性进度条，项目生命周期收进右上角状态控件；
- 页面区分服务年度、当前工作、目标封存期和下一里程碑；
- 年度范围、监测计划和数据采集改为并行表达；
- 2026 项目的报告、核查、Finding 整改、重算和封存可以跨到 2027 Q1；
- 服务启动授权和未完成年度项目创建阶段不展示 Agent；
- 新增 `packages/agent/domain/annual-project-view-model.js`，年度页的项目、范围、计划、角色、周期和里程碑文案由业务对象派生；
- 新增 `packages/agent/domain/agent-context.js`，Agent 按年度项目、工作流、期间和具体对象构建上下文，并按 context key 隔离会话；
- 179 项自动化测试与年度项目、首次进入、引导流程、Agent Context 浏览器审查均通过。

### 动态数据契约

以下内容必须由年度项目及关联对象动态生成，不得固定在页面模板中：

- 企业、服务年度、项目编号、当前状态、目标封存期；
- 当前季度 / 当前工作流、下一里程碑和下一交付；
- 服务范围、产品 / CN Code / 设施数量与受控版本；
- 监测计划编号、版本、状态、数据源和责任人；
- 项目角色、季度包状态、核查 Finding、整改与重算状态；
- Agent 的年度项目、工作流与对象上下文。

固定内容仅限产品规则、字段标签、流程解释和不随项目变化的合规说明。

### 尚未完成

- Agent 已在本地原型中实现 `annualProjectId + serviceYear + workstream + objectRef` 运行时契约与本地会话恢复；服务端权威解析、跨设备持久化和不可变审计仍未实现；
- 多年度并行项目切换器、真实文件上传、服务端授权、外部核查协作和正式计算 / 交付命令仍需后续实现；
- 当前页面仍是静态可验证原型，不能把 ViewModel 的演示对象表述为生产数据。
