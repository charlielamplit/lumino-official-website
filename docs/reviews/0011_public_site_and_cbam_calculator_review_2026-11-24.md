## 结论与范围

**当前工作树不满足正式发布验收。** 此结论针对 `Demo/lumino-site` 的当前文件快照；计算器与线索 API 有其他 Agent 的未提交修改，本次未改动其代码。正式站 `https://intl.luminoyou.com/` 因本机 DNS 和浏览器控制宿主不可用，未完成线上交互验收。`origin/dev` 本地引用中已有 PR #119 的后续官网修正，但这些修正不在当前检出的 `docs/leads-database-proposal` 工作树里，不能把两条代码线合并视为一个已发布版本。

本次核查了官网 Advisor → 联系表单 → 线索 API，以及计算器的默认、混合、推测实测情景。运行 33 项相关自动测试，全部通过；这些测试未覆盖以下截图算例及法规口径差异。

## 截图算例：CN 72189980 的混合情景为何为 ¥0

截图所示前体为“高碳铬铁（72024100）”，SEE 显示约 1.04 tCO₂e/t，免费配额扣减后净排放为 0。按当前数据和该 SEE 反推，模型给出的前体消耗量约为 0.25 t/t。独立代入当前代码得到：

| 当前计算步骤 | 数值 |
|---|---:|
| 成品自身工序参考排放 | 0.45 tCO₂e/t |
| 前体 `72024100` 未加价默认值 × 推测消耗量 | 2.35 × 0.25 = 0.5875 tCO₂e/t |
| 混合 SEE | 1.0375 tCO₂e/t |
| 当前免费配额扣减 | `max(成品 A 列 0.36 + 前体 B 列 0, 成品 B 列 1.42) × 0.975` ≈ 1.3845 tCO₂e/t |
| 当前净排放 / 1 吨成本 | 0 / ¥0 |

这里的 **0 是当前输入和算法的产物，不能据此判断客户真实 CBAM 义务为 0**。更关键的是，`72024100` 不在本地完整 CN 清单，也没有对应 benchmark；API 仍接受它，从 6 位父级取得默认排放，却把前体的免费配额基准当成 0。随后 `bmEffective()` 强制以成品整链 B 列基准 1.42 兜底，覆盖了实测/混合情景应使用的递推结果。

欧委会 [免费配额计算指南第 2.2.1.1–2.2.1.3 节](https://taxation-customs.ec.europa.eu/document/download/3aa2c730-4f1b-4524-8f71-d9cfe4880ac7_en?filename=Guidance+No.+4+-+CBAM+calculation+of+the+free+allocation+adjustment+to+the+number+of+CBAM+certificates+to+be+surrendered.pdf)将复杂商品实测口径写为成品工序免费配额 + 各前体消耗量 × 前体免费配额；成品 B 列用于**成品整体采用默认值**的情形。假设另经确认前体为 `72024190`、消耗量仍为 0.25 t/t、使用其 2026 年默认值 2.585 和 B 列基准 1.142，则示意计算为 `SEE = 0.45 + 2.585 × 0.25 = 1.09625`、`SEFA = (0.358 + 1.142 × 0.25) × 0.975 = 0.6274125`、净额约 `0.46884 tCO₂e/t`。仅为说明差异，按页面固定 Q1 价格 €75.36 和汇率 7.8，1 吨约 **¥276**。前体细码、消耗量、工艺路线和实际排放均未获企业证据确认，这不是可申报金额。

## 必须修复（P0）

1. **混合/推测实测情景错误使用成品 B 列作为最低免费配额。** `apps/site/calculator/realtime-cost.mjs:21-25,36-42` 的 `Math.max(bmA + precursorBmAddition, bm)`直接造成上述 0。混合情景应按成品 A 列与已确认的前体 SEFA 递推；纯默认情景才取成品 B 列。缺少前体基准时应显示“无法计算/待确认”，不可用 0 或成品 B 列暗中补齐。
2. **AI 返回的前体码和系数未通过计算资格验证，且可能漏掉主要投入。** `api/precursors.js:78-104` 对 `72024100` 这类不在完整清单的代码、缺失 benchmark、非正消耗量和不适用的同层物料没有拒绝；`api/_lib/precursor-filter.js` 虽有一层筛选函数，却没有被 API 调用。模型提示词 `api/_lib/precursor-model.js:31-48` 又要求“通常只需 1 个”；欧委会[钢铁行业指南表 4-11](https://taxation-customs.ec.europa.eu/document/download/3eb64513-8255-4c71-875a-bd0a8c7ff772_en?filename=Guidance+No.+5d+-+Sector-specific+guidance+document+on+iron+and+steel.pdf)的不锈钢工艺示例同时列有外购粗钢、FeNi、FeCr 和 FeMn。截图只列 FeCr，尚无证据证明其他受管控投入不存在。应先校验完整 CN、业务生产路线、全部直接上一层投入、消耗量范围、国别和必要表项；不确定时让用户确认，不能展示正式三情景金额。
3. **当前工作树的线索提交仍可把失败标为解锁成功。** `apps/site/calculator/app.js:559-629` 在 5xx、404、400 和网络失败时设置 `leadCaptured=true`、写入 `localStorage`、清空表单并继续；`596-604` 只凭 HTTP 成功称“线索已记录”，未检查 `data.persisted === true`。这既使失败线索丢失，又与官网“正式保存才算提交”的既定门禁冲突。联系页 `apps/site/site/contact.js:91-100` 仍显示“演示记录”，与当前拟上线文案不一致。

## 发布前修复（P1）

4. **混合前体使用未加价的 `total`。** `api/precursors.js:84-92` 取 `def.total`，而同一数据项另有 `seeWithMarkup`；截图例为 2.35 与 2.585。应按 [（EU）2025/2621 经（EU）2026/1740 校正后的适用默认值规则](https://eur-lex.europa.eu/eli/reg_impl/2026/1740/oj/eng)核对年份、国别和排放范围，并让前体默认值选择与成品默认值同一函数完成。
5. **“纯实测”并无企业实测数据。** `api/precursors.js:87-93` 使用行业 `actual-full.json` 参考并用 `Math.min()` 压到默认值；`apps/site/calculator/app.js:645-650` 的成品自身工序同样来自估算表。成品/前体的企业实际消耗、设施、生产路线、期间、原产国及核查证据都未输入。应改称“行业参考估算”，并阻止其被误用为法定实测或确定节省率。
6. **已付碳价扣减公式不对。** `apps/site/calculator/realtime-cost.mjs:43-49` 将碳价乘到扣除免费配额后的净排放；官方 [CBAM 概念指南第 2.4.2 节](https://taxation-customs.ec.europa.eu/document/download/031abf60-21a9-4822-b258-ac8b111d8358_en?filename=Guidance+No.+1+-+Introduction+to+CBAM+concepts.pdf)的证书公式是 `max(0, SEE - SEFA - SECPP / 证书参考价) × 数量`，其中 SECPP 是针对商品的**有效已付碳价**，并须满足 [（EU）2026/2498 的证明要求](https://taxation-customs.ec.europa.eu/news/cbam-commission-adopts-rules-recognition-carbon-prices-paid-non-eu-countries-2026-11-16_en)。当前只有一个“¥/tCO₂e”输入，无法表达覆盖排放、返还与证明状态。
7. **价格和期间被固定。** `apps/site/calculator/data/parameters.json` 一律使用 €75.36、汇率 7.8；欧委会[2026 证书价格表](https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/price-cbam-certificates_en)显示 Q1 €75.36、Q2 €75.28、Q3 €82.32，Q4 当时未公布。页面只收年度总量，不能按进口季度分摊；2027 起为周价。结果应明确标为价格假设，或增加期间分配。
8. **切换产品/年份后旧结果仍可驱动 AI。** `apps/site/calculator/app.js:126-152,196-209,509-515,688-693` 隐藏了 AI 面板，但未清空 `latest/defaultBasis`；未重新点击“计算”就能在新 CN 下用旧产品描述请求前体，并在新旧输入之间混算。应使结果失效，直到新输入完成重算；异步请求需绑定产品键并中止旧请求。
9. **前体失败仍显示三种有效金额。** `apps/site/calculator/app.js:660-668,695-711` 不论 API 错误或空结果都设置 `aiReady=true`；混合和纯实测可能显示无前体的成品工序金额。应区分“确认无 CBAM 前体”和“模型失败/数据缺失”，后一种不提供金额。
10. **当前工作树没有整合已合入 `origin/dev` 的 Advisor → 留资修复。** 当前 `advisor-widget.js` 无 `interactionId` 归因，`contact.js` 不检查 `persisted`，公开隐私/Cookie 页仍有“演示”字样；本地 `origin/dev` 已含 PR #119 的相应更新。先确定发布基线，再做三方合并并回归，避免用旧页面配新 API。

## 已确认的有效部分与验收门禁

- Advisor 代码有预置回答、自由问题模型路径、超时回退、敏感信息拦截和来源展示；当前 33 项相关测试通过。自动测试不能证明线上模型、超时、真实留资与通知链路已通过。
- 计算器把成品默认值与推测情景分开显示，且前体页脚提示“非企业法定实测值”；这种提示需要覆盖情景名称和节省率文案。
- 正式上线前至少用 `72189980 + 高碳铬铁`、钢坯→钢材、熟料→水泥、铝锭→铝材做独立手算；覆盖有/无前体、错误 CN、缺基准、不同国别与年份、碳价、API 失败。每例应留输入、来源、逐项公式、期望值、页面值和误差。
- 正式站验收需核对首页/服务页/计算器/Advisor/联系页的实际 release SHA，再跑预置、模型、追问、超时、人工服务五条路径和真实数据库/通知状态。当前无法确认线上版本，故本报告不作“已发布通过”结论。

## 修复进度（同日后续工作树）

1. 成品实测参考/混合情景的免费配额改为 `成品 Column A + Σ 前体 Column B × 消耗量`，取消成品 Column B 下限；只在纯默认情景使用成品 Column B。构建成本基准时保留原始精度，且不再把成品工序估算裁剪到默认值或强行补成完整链路。
2. 前体 API 校验完整 CN 码、默认因子、Column B、行业参考值和消耗量。模型返回 `72024100` 时，只有其 6 位品类下所有有效细码的默认、基准、行业参考参数一致才映射，并向用户展示映射和分类待核实提示；否则返回 422，不展示三情景。模型提示词允许多个直接投入，API 给模型当前 CN 清单，并可输入工艺及直接外购投入说明。前体消耗量可在结果页调整。
3. 混合前体改用年度加价默认值，并按商品适用范围剔除未计入成本的间接排放。行业参考前体值不再用 `min(参考值, 默认值)` 人为压低。三个情景的文字均明确行业参考性质。
4. 已付碳价按 `max(0, SEE − SEFA − 有效已付碳价对应证书数)` 计算；页面说明输入值假定覆盖全部嵌入排放且扣除退税，正式抵扣仍须凭证。
5. 欧委会 2026 年 Q1/Q2/Q3 证书价分别为 €75.36/€75.28/€82.32，Q4 尚未公布。本站自动计算已公布季度算术均价 €77.6533，显示为 €77.65，并支持选择已公布的单季度价格；2027 年及以后只把该均价当作参考假设，不能冒称官方周价。来源：<https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/price-cbam-certificates_en>。
6. 切换成品或年份使旧结果失效，前体异步响应按成品、年份、工艺说明绑定；服务出错时不展示三情景。计算器人工咨询仅在 API 确认 `persisted === true` 后显示成功；官网联系页和 Advisor 归因与本地 `origin/dev` 已合入实现对齐，并保留现有 Postgres 工作树改动。AI 推算的留资门槛按后续用户要求重新加入，见下文。
7. 计算器和隐私页补充说明：基础试算在浏览器进行，主动使用 AI 推算时 CN 码及自填工艺说明会经服务端发送至配置的模型服务；避免把两种数据路径混写。
8. 本地顾问真实请求暴露出无来源模型会把正式期年度申报说成季度申报。对“CBAM 是什么”类基础问题改为欧委会来源支持的固定答复；其他未匹配资料的自由回答显式标为“通用参考，未匹配到可引用资料”，并收紧提示词，禁止无来源时声称已核对官方公告。上游模型曾出现一次连接失败，接口按设计回退到基础引导；重试成功后返回固定答复。
9. 官网原有三组“项目案例”写成具体客户已完成项目，但仓库里没有相应授权或交付证据。首页、案例页和页脚现统一改为“典型服务场景”，移除地区与已完成成果断言，并在案例页显著说明场景仅用于介绍可能的服务工作；本地 Chrome 已检查页面实际渲染。

**复算证据：** 对截图 CN `72189980`，取可等值映射的铬铁前体、消耗量 0.25 t/t，则混合 SEE 为 1.09625、SEFA 为 0.6274125、净排放为 0.4688375 tCO₂e/t，按已公布季度算术均价及 7.8 汇率约 ¥283.97/吨。实际模型在没有工艺说明的一次本地运行中推测了 `72181000` 不锈钢锭，混合情景显示约 ¥3,134/吨；这说明不同供应链路径会产生显著差异，不能把任一路径视作企业实测值。

**验证：** `node --test tests/*.test.cjs tests/*.test.mjs` 共 122 项通过；Advisor 扩展测试 31 项通过、1 项无模型密钥跳过，已同步过时的模型路由测试断言；`git diff --check` 通过。Chrome 中已检查 4188 页面的季度价格、`72189980` 三情景和服务场景页面。补充工艺“外购高碳铬铁、镍铁和生铁”后，真实模型返回三项有效前体，混合成本约 ¥922/吨；把铬铁消耗量由 0.25 改为 0.3 吨/吨后，混合成本重算为约 ¥966/吨；切换 Q2 价格后混合情景为约 ¥937/吨。顾问 API 对“CBAM 是什么”返回欧委会来源支持的正式期、年度申报答复。平台数据库集成测试需要访问并改写本地 PostgreSQL，共享工作树内另一 Agent 正在处理相关数据库改动；本轮沙箱连接返回 `EPERM`，未以提升权限重跑，也未据此声称真实线索持久化或通知链路通过。当前工作树仍有其他 Agent 的未提交数据库及部署改动，正式站的发布版本未在本次验证。年度总量未按实际进口季度拆分；2027 年后官方周价公布前，本站只能提供参考情景。前体 CN、消耗量、生产路线和企业实测排放须以真实材料确认。
