# CBAM 正式客户材料文件切片验收（2026-11-28）

基线：`dev` 的材料计划草稿已经绑定租户、年度项目、设施和季度。本切片新增受控文件证据链，默认关闭。

## 已实现

- 客户在 CBAM 当前工作中的天然气用量材料草稿下上传 UTF-8 TXT/CSV，单份 2 MiB 以内；管理员、负责人和资料协作者可上传。文件由服务端代理写入私有 COS；浏览器不接触 COS 凭证或对象键。
- 服务端从 Bearer 会话和数据库校验租户、角色、项目与材料草稿归属。每次上传产生唯一对象键、版本、SHA-256 与审计事件；只有 `STORED` 版本出现在客户工作台。下载重新校验大小和摘要。其他租户及演示租户不可访问正式客户文件。
- 上传开关 `PORTAL_EVIDENCE_UPLOAD_ENABLED` 默认关闭；COS 配置不完整时界面显示关闭说明，API 返回 503。关闭时的工作台无需查询新证据表，便于先发布代码、后执行迁移与开通。
- COS 上传失败时记录 `FAILED` 且不可下载。存储成功而数据库确认失败的对象不会对客户可见，需由运维清理孤儿对象。

## 已验证

- 本机 PostgreSQL 集成：跨租户读写、版本递增、伪造租户字段、无效文件、COS 失败、对象篡改后的下载拦截。
- 平台全量 44 项测试通过；客户 Portal 浏览器回归覆盖登录、引导、材料草稿、上传关闭态、演示隔离及 320/390/768/1440px。
- SDK 3.0.0 在隔离工作树实际安装并验证 `putObject`、`getObject` 接口存在；未连接真实 COS 桶，真实云上传尚未验收。

## 开通门禁与下一步

1. 确定 COS 数据区域和账号，创建私有桶；给服务端凭证只授予 `portal-evidence/*` 的 `PutObject`、`GetObject`。确认传输与静态加密、备份、留存期限、对象清理及凭证轮换。
2. 确认正式 PostgreSQL，先执行迁移 007，再配置环境变量并开启开关。在真实 COS 桶用两家隔离测试租户完成上传、下载和断电/失败恢复验收。无需腾讯轻量存储服务器。
3. PDF 与扫描文件进入正式链路前增加恶意文件扫描和隔离区；随后将账单提取任务、候选数据、人工确认和申报数据血缘绑定到 `portal_evidence.id`。模型网关数据处理与留存约定需确认。
