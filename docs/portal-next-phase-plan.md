# Lumino 官网与 Portal 下一阶段计划

## 0. 当前执行检查点

- Phase 0 已完成：前端消费契约见 `portal-asset-consumption-contract.md`。
- Phase 1 已完成：CBAM、PCF 与平台页已经按不同专业结构深化，并通过 390 / 768 / 1440px 审查。
- Portal 权限加固已完成首轮：试算参数输出转义、客户深链守卫、PCF 独立复核职责分离、报告与快照锁定链路均已加入专项浏览器审查。
- Phase 3 第一切片已完成：资产概览、详情、胶囊和修订影响通过只读 ViewModel 投影，并有跨租户／敏感资产负向测试。
- 当前下一步：把“我的任务”和“交付中心”从页面硬编码数组改为统一授权投影；PCF 计算结果仍为演示数据，不得宣称已接生产核算。

## 1. 决策摘要

Portal 不能判定为“已经没有问题”。当前成果是可验证的静态交互原型：多服务壳层、CBAM 频道、PCF 最小闭环、共享中心和数据资产内核已经成立，但真实数据接入、权限、跨服务聚合与完整 PCF 管道尚未完成。

下一阶段采用两条并行工作流：

1. **表达与体验工作流**：先深化 CBAM、PCF 服务页和平台介绍页，同时完成 Portal 数据资产中心的 UX 消费契约；这部分不改底层资产语义。
2. **数据资产工作流**：由并行 Agent 继续负责资产版本、Schema、血缘、权限、更新影响和服务绑定；完成接口检查点后再进入 Portal 集成。

暂不扩建 ESG、企业碳盘查、碳资产与绿证、出口合规的业务工作流，也不接入真实认证、数据库、核算、报告或 CRM 后端。

## 2. 当前可依赖基线

### 2.1 已成立

- 统一 Portal 壳层和六项服务契约；公开站与 Portal 共用服务 ID、状态和主要操作。
- CBAM 为已开通频道，PCF 为试点频道，其余服务保持咨询或规划状态。
- 企业资产、不可变版本、服务绑定、Agent 提议、Snapshot、Transformation、CalculationRun 和 STALE 传播已有原型内核与 Schema。
- CBAM 与 PCF 可以引用同一资产版本，同时保留独立服务确认状态。
- 首页、平台页、六项服务页及 Portal 已通过基础路由、语义和响应式审查。
- 当前自动化测试覆盖服务契约、工作流、数据资产和试算器。

### 2.2 尚未成立

- 数据资产中心还不是完整的业务操作界面，更新影响、访问边界和历史版本的表达不足。
- “我的任务、数据资产、交付中心”的聚合仍主要依赖 Mock 数据。
- PCF 尚未实现完整模板契约、运行时 Schema 校验、七步审计管道和正式报告锁定。
- 真实认证、租户隔离、持久化、异步任务、文件存储、计算和报告服务均未接入。
- Portal 的错误恢复、空状态、权限拒绝和移动端连续任务仍需要专项审查。

## 3. 所有权与并行边界

| 工作域 | 主要所有者 | 可并行事项 | 合并前检查点 |
|---|---|---|---|
| 资产语义、版本、血缘、权限 | 数据资产 Agent | 文档、内核、Schema、负向测试 | 发布版本号、变更记录和兼容说明 |
| 公开站内容与视觉 | 官网／Portal Agent | CBAM、PCF、平台页、共享营销样式 | 不新增未经登记的公开声明 |
| Portal UX 契约 | 官网／Portal Agent | 页面结构、字段需求、状态和恢复动作 | 字段必须映射到资产框架，不新建平行模型 |
| Portal 数据接入 | 双方共同 | 适配层、绑定、影响预览、角色投影 | 接口和错误模型双方确认后实施 |
| PCF 专业管道 | PCF 服务层 Agent | 模板、清单、因子、计算、报告 | 资产版本和快照契约稳定后实施 |

并行期间，官网／Portal Agent 不得修改 `packages/agent/domain/data-asset-engine.js`、`packages/agent/schemas/` 或资产框架的核心语义；数据资产 Agent 不得在未同步的情况下重写 Portal 页面结构和公开服务文案。

## 4. 分阶段执行计划

### Phase 0 — 基线锁定与接口检查

目标：让两个工作流在同一事实基础上工作。

任务：

1. 读取资产框架最新版本与变更记录，不以聊天历史代替文件。
2. 运行现有测试并记录基线结果。
3. 输出 Portal 前台需要的数据字段和动作清单。
4. 确认资产 ID、版本 ID、绑定 ID、快照 ID、计算运行 ID 的稳定命名。
5. 确认数据资产 Agent 正在修改的文件，避免并发覆盖。

产物：

- 本计划和 `portal-next-phase-handoff.md`；
- 一份经过双方确认的前端消费契约或字段映射；
- 基线测试记录。

退出条件：不存在两个不同的资产模型或状态来源。

### Phase 1 — 深化 CBAM、PCF 与平台公开表达

目标：让外部访客理解“为什么选择 Lumino、需要提供什么、最后得到什么”，而不是只看到服务目录。

任务：

1. 深化 `/services/cbam/`：适用判断、范围与编码、数据准备、计算、核查支持和进口商交付。
2. 深化 `/services/pcf/`：模板导出／回传、功能单位、系统边界、生命周期清单、活动数据、排放因子、分配、计算、热点、复核与报告版本。
3. 优化平台介绍页：用真实工作机制说明“资产 → 服务绑定 → 正式事实 → 快照／计算 → 受控交付”，不复制 Portal 截图。
4. 统一 Header、Footer、状态词、CTA、排版节奏和移动端首屏。
5. 更新公开声明登记表；试点和规划能力继续使用条件式表达。

依赖：无底层代码依赖，可以立即执行。

退出条件：

- 三页各只有一个核心问题、一个 `h1` 和一个主要操作；
- CBAM 与 PCF 的专业结构不同，不使用同一模板生硬复制；
- 所有能力声明可在 `public-claims-register.md` 中追溯；
- 390、768、1440px 无整页横向溢出。

### Phase 2 — Portal 数据资产 UX 契约

目标：先设计用户如何理解和处理数据资产，再接底层实现。

资产概览必须回答：

- 当前最需要处理的是什么；
- 哪些资产缺确认、即将过期或存在质量问题；
- 哪些服务正在使用这些资产；
- 哪次修订会影响计算或交付。

资产详情必须回答：

- 资产是什么、属于谁、覆盖什么对象与期间；
- 原始来源、当前版本、确认状态和数据质量；
- 服务绑定及其独立确认状态；
- 血缘、快照、计算和交付影响；
- 可访问角色、历史版本和下一步动作。

必须设计的恢复状态：

- 无权限：说明缺少的权限和申请入口；
- 新版本待确认：展示差异及受影响对象；
- 计算已过期：说明原因并提供重算入口；
- 来源撤销或文件缺失：保留历史引用并提示替代路径；
- 无资产：从上传、模板或已有主档中选择下一步。

依赖：只依赖资产框架字段定义，不依赖真实后端。

退出条件：完成字段映射、状态矩阵、桌面与 390px 原型，并经数据资产 Agent 审查不存在语义冲突。

### Phase 3 — 数据资产中心集成

目标：以资产内核为唯一来源替换页面中的重复 Mock 和硬编码引用。

任务：

1. 建立只读适配层，把资产内核对象投影为页面 ViewModel。
2. 实现资产概览、分类列表和详情 Drawer。
3. 实现版本历史、服务使用情况和确认记录。
4. 实现“修订影响预览”：列出将进入 STALE 的快照、计算和未锁定交付物。
5. 扩展负向权限：跨租户、跨对象、跨服务和未授权字段均不得显示。
6. 将 CBAM／PCF 的企业、设施、产品、活动数据和证据入口统一指向资产池。

依赖：数据资产 Agent 发布稳定接口、Schema 和错误模型。

退出条件：

- 页面不直接改资产存储，只调用公开能力；
- 同一资产可被 CBAM、PCF 绑定，确认状态互不污染；
- 修订不会自动切换服务绑定；
- 锁定报告仍能重现旧资产版本；
- 负向权限测试通过。

### Phase 4 — PCF 完整业务切片

目标：把当前最小演示链路提升为符合专业核算逻辑的可验证原型。

任务顺序：

1. 核算声明：目标、用途、受众、产品、功能单位、参考流和期间。
2. 系统边界：生命周期阶段、纳入／排除、截断规则和理由。
3. 模板：按当前范围导出版本化模板，回传后执行结构和单位校验。
4. 清单：材料、能源、运输、产量、共产品、分配和证明材料。
5. 因子：来源库、数据集 ID、版本、地域、年份、单位和适用理由。
6. 计算：锁定输入快照，执行确定性计算并生成新 Run，不覆盖历史。
7. 解释：阶段结果、热点、数据质量、不确定性、敏感性和限制。
8. 复核与报告：专家复核、模板版本、报告修订和受控交付。

约束：Agent 只能提出结构、映射和异常建议，不能自动确认系统边界、功能单位、分配规则、因子适用性或正式结论。

依赖：Phase 3 完成；PCF 实施需继续遵循 `pcf-calculation` 与 `pcf-report` 专业能力约束。

退出条件：PCF 主路径、空数据、模板错误、单位错误、缺资料、计算失败、无权限、STALE 和报告未就绪均有恢复动作。

### Phase 5 — 共享中心和全站一致性

目标：让“我的任务、数据资产、交付中心”真正成为跨服务共享能力。

任务：

1. 我的任务只聚合用户获授权对象，并显示服务、对象、责任人、截止状态和下一步。
2. 数据资产显示文件、结构化事实、版本和被哪些服务使用，不混淆资产确认与服务确认。
3. 交付中心显示报告、版本、审批、锁定和交付状态，操作跳回对应服务频道。
4. 官网、平台页、服务页和 Portal 使用同一名称、状态和责任边界。
5. 统一空状态、错误恢复、Drawer、Toast、焦点返回和移动导航。

退出条件：不存在跨服务或跨角色数据泄露；所有聚合项都能回到可执行对象。

## 5. 审查门禁

### Gate A — 资产契约

- 资产框架版本、Schema 和实现版本一致；
- 页面字段均有来源，不出现仅为 UI 创建的第二套正式状态；
- Agent 提议与正式事实分离；
- 服务绑定锁定明确的资产版本。

### Gate B — 业务真实性

- CBAM 与 PCF 的状态和能力边界真实；
- Mock、试点、规划和真实交付明确区分；
- 不出现虚构客户、资质、效果数字或后端能力；
- 报告、专家复核和法规声明带条件或来源。

### Gate C — UX 与视觉

- 每页只有一个 `h1` 和一个视觉主操作；
- 普通用户先看到待处理问题，而不是 Schema 字段目录；
- 390、768、1440px 无整页横向溢出；
- 键盘可以完成主路径，动态反馈具备正确 ARIA 语义；
- 不使用卡片墙、AI 控制台、装饰性指标或大面积无意义留白。

### Gate D — 工程与回归

- `node --test tests/*.test.* packages/agent/tests/*.test.*` 通过；
- JavaScript 语法检查和 `git diff --check` 通过；
- 核心路由返回 200，无浏览器控制台错误和破损资源；
- 数据资产、服务契约、CBAM 状态机和 PCF 状态迁移无回归；
- P0／P1 清零，P2 必须登记责任人和后续版本。

## 6. 不在本阶段做的事情

- 不为未开放服务创建虚假工作空间；
- 不建设生产认证、数据库、文件存储、消息队列或 CRM；
- 不让页面绕过资产内核直接修改正式事实；
- 不把 Agent 输出直接视为正式计算输入或合规结论；
- 不在数据契约尚未稳定时大规模重写 Portal；
- 不进行破坏性 Git 操作，不覆盖其他 Agent 或用户的未提交修改。
