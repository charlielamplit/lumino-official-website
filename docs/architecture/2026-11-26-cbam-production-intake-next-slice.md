# CBAM 收资生产化：下一段实施基线

日期：2026-11-26

## 当前起点

- Portal 登录入口将固定样例限定在本机演示入口或专用演示租户。普通客户邮箱通过服务端会话进入独立初始化页，确认企业并建立 `SETUP_DRAFT` 年度项目；样例工作流不会在客户页渲染。完整客户工作流和文件授权仍待接入。
- E-02 单份季度天然气账单的模型提取、人工确认与本机刷新恢复已可演示。
- 浏览器角色、年度项目、资产、任务和业务事实仍由演示状态及 `localStorage` 驱动。本机 `.local-data/portal-intake/` 只保存测试文件、候选和确认摘要。
- PostgreSQL 已覆盖租户、用户、成员资格、客户与员工分离的会话、审计、线索及 CBAM `SETUP_DRAFT` 年度项目；尚无设施、材料请求和客户文件的服务端权威记录或私有对象存储。

## 下一段交付范围

先完成一个可用真实权限模型验证的 E-02 闭环：

1. **客户身份与范围**：客户登录/会话、企业确认和 `SETUP_DRAFT` 年度项目已落地。下一段要让服务端持有设施、材料请求及年度项目后续状态，并按成员角色管理它们。客户端传入的租户、角色、年度和对象编号只作定位提示。
2. **受控文件**：服务端签发或代理上传到私有对象存储；记录 SHA-256、大小、MIME、上传人、所属租户/项目/设施/材料请求、对象键与版本。原文件不可覆盖；更正产生新证据版本。
3. **候选与任务**：模型任务按证据摘要和材料请求版本幂等执行；保存提取器/模型版本、原文定位、提议值、校验结果及失败原因。模型结果只进入待确认状态。
4. **确认事务**：服务端再次校验会话、角色、租户、当前请求版本、证据摘要和候选版本；在一个数据库事务中写入已确认事实、状态变更与只追加审计。重试不能重复生成事实。
5. **恢复与读取**：同一租户中获授权的用户换浏览器或设备后可取回材料请求、候选、已确认事实和经授权的原文件；浏览器缓存不是权威来源。

本段只覆盖 E-02，不以此宣称完整 CBAM 核算、监测计划或年度排放报告已可交付。

## 服务端对象最小字段

| 对象 | 必需字段/约束 |
|---|---|
| 年度项目 | `id`, `tenant_id`, `service_year`, `status`, `revision`；访问按活动成员资格与项目授权过滤 |
| 材料请求 | `id`, `tenant_id`, `annual_project_id`, `facility_id`, `period`, `data_item_code`, `status`, `revision` |
| 证据 | `id`, `tenant_id`, `request_id`, `object_key`, `sha256`, `byte_length`, `media_type`, `filename`, `uploaded_by`, `created_at`, `supersedes_id`；对象键不可由客户端决定 |
| 提取候选 | `id`, `tenant_id`, `request_id`, `evidence_id`, `request_revision`, `extractor_version`, `model_version`, `value`, `unit`, `source_locator`, `validation_status`, `revision` |
| 已确认事实 | `id`, `tenant_id`, `request_id`, `candidate_id`, `evidence_id`, `metric_code`, `value`, `unit`, `confirmed_by`, `confirmed_at`, `revision`；同一请求/指标的当前版本唯一 |
| 审计 | 操作者、租户、对象及前后版本、动作、理由、时间、请求 ID；只追加，不存原文件正文或模型密钥 |

## 接口与拒绝条件

- 所有写入及文件下载要求服务端会话；缺失/失效会话返回 401，跨租户/不存在项目或对象对外统一返回 404，角色不足返回 403，过期版本返回 409。
- 上传先校验文件类型、大小和材料请求；服务端重新计算摘要。对象存储成功而数据库提交失败时，记录待清理对象并重试/回收，不能显示“已提交”。
- 候选确认只接受服务端保存的当前候选 ID 和预期修订号；任何浏览器 `demoRole`、`tenantId`、`confirmedBy` 都不能替代服务端身份。
- 证据读取需要重新授权并记录访问；直接对象键或公开 URL 不可作为下载权限。
- aiberm.com 的输入留存、日志、训练及处理地区需在真实客户账单启用前由业务/法务确认，并与用户告知一致。

## 可执行验收

1. 用两个独立租户和两个浏览器完成上传、提取、确认、刷新与跨设备读取；同租户获授权用户能恢复，另一租户不能枚举或下载。
2. 篡改角色、租户、设施、材料请求 ID、文件摘要、候选值或版本时均拒绝；不生成业务事实。
3. 同一任务重复提交、超时重试和重复点击确认只产生一份当前事实；旧证据和候选可追溯但不可作为当前值。
4. 下载文件与上传时 SHA-256 一致；原文件、候选、事实、审计可从同一请求追溯。
5. 数据库或对象存储故障时页面明确提示未完成；恢复后可安全重试，不能出现“页面已确认但服务端无事实”。
6. 备份、恢复、删除/留存与审计方案通过演练后，再允许真实客户材料进入该链。

## 腾讯云资源决策

当前不需要购买轻量存储服务器。正式接收客户文件时优先使用**私有 COS 存储桶**，由服务端身份访问；结构化数据沿用/扩展受控 PostgreSQL，异步提取使用 Worker。实施前需确认数据驻留区域、COS 所在账号、服务器/应用到 COS 的最小权限方式、加密与版本/留存策略、备份以及现有 PostgreSQL 是否为正式环境。没有这些配置时，接口保持关闭，不回退到本机文件或浏览器缓存。
