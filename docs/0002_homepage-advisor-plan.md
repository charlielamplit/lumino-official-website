# 0002｜Lumino 官网右下角对话顾问 Plan

> 文档类型：产品设计与实施计划
> 版本：1.1.0
> 日期：2026-11-02
> 状态：待确认后进入实施
> 适用范围：Lumino 官网首页及后续可复用的公开站页面
> 暂定名称：Lumino 服务顾问 / Lumino Service Guide

## 1. 决策摘要

在官网右下角提供一个固定入口，用户可随时展开为轻量对话浮窗。浮窗同时支持：

- 从预选话题开始；
- 输入自由问题；
- 通过逐段流式、近似“打印式”的方式显示回答；
- 推荐相关服务、知识文章和下一步准备事项；
- 引导用户前往联系页或发送邮件。

该功能定位为**官网服务分诊与常见问题顾问**，不是万能法规机器人，也不承担正式法律判断、CN 编码认定、正式核算、认证结论或项目报价。

第一版不在聊天窗口直接收集姓名、电话、邮箱或客户生产资料。当前尚未接入正式数据库，因此转化动作只引导至联系页和公开邮箱；正式留资在数据库、隐私流程和责任人确认后作为第二阶段能力启用。

对话运行采用“**固定答案与工具路由优先，模型兜底**”的原则。预选话题、高频 FAQ、服务分诊和已有工具入口应优先由确定性规则回答，只有开放问题、复杂解释或需要组合多份已发布资料时才调用模型。

## 2. 产品目标

### 2.1 用户目标

帮助第一次访问网站的出口、外贸、关务、采购、生产、财务和 EHS 人员快速完成：

1. 判断自己的问题大致属于哪项服务；
2. 理解一个基础概念或常见要求；
3. 知道还需要确认什么事实；
4. 获得可执行的资料准备建议；
5. 进入正确的服务页、知识文章或联系入口。

### 2.2 业务目标

- 降低用户理解六项服务的门槛；
- 提高服务页、知识页和联系页的有效访问；
- 在不夸大能力的前提下形成初步需求分诊；
- 为未来正式留资建立可评估的对话基础；
- 形成可维护、可审核、可回归测试的官网 Agent 能力。
- 让预选话题、高频 FAQ 和工具路由在不调用模型时仍可完整使用；
- 减少本可由已审核答案或现有工具完成的模型请求、延迟和成本。

### 2.3 非目标

第一版不提供：

- 正式法律意见、监管认定或保证性答复；
- 确定某个 HS/CN/TARIC 编码必然属于或不属于 CBAM；
- 正式排放计算、项目报告或核查结论；
- 自动报价、项目周期承诺或认证保证；
- 账单、BOM、供应商声明等正式客户文件上传；
- 客户 Portal 项目、资产或历史记录查询；
- 聊天窗口内直接留资和自动创建正式销售线索；
- 默认访问互联网并即时解释未经审核的最新法规。

## 3. 核心体验原则

1. **先帮助，再转化**：至少先完成一次有价值的回答，再展示联系动作。
2. **一次只问一个问题**：不把法规表格直接搬进聊天窗口。
3. **问业务事实，不问专业术语**：例如询问产品、市场、客户要求和截止时间，而不是要求用户先理解法规字段。
4. **预选与自由输入并存**：新用户可以点击话题，明确需求的用户可以直接输入。
5. **回答有边界、有来源**：法规性或方法性回答必须关联已审核来源。
6. **无法确认就停止**：检索不到可靠依据时明确说明，不依靠模型记忆补齐。
7. **不暴露内部成熟度**：对外只说明 Lumino 可提供的服务和边界，不展示 `PILOT`、`PLANNED`、人工/系统覆盖程度等内部治理信息。
8. **不制造送达假象**：没有正式数据库时，不宣称问题、联系方式或聊天记录已经进入服务团队流程。
9. **确定性能力优先**：可以由已审核固定答案、服务映射或现有工具完成的任务不调用模型。
10. **工具完成任务**：用户意图已匹配试算器、知识文章或联系入口时，直接给出用途说明和可操作链接，不用模型重复该工具的功能。

## 4. 入口与浮窗布局

### 4.1 入口策略

现有右下角已有“工具”入口，不再增加第二个悬浮按钮。实施时采用以下二选一方案，推荐方案 A：

#### 方案 A｜统一入口（推荐）

- 将现有右下角“工具”入口升级为统一工具入口；
- 第一项为“问 Lumino”；
- 其余保留 CBAM 成本计算器、PCF 初步估算、企业排放估算和绿电需求测算；
- 点击“问 Lumino”后，在同一位置展开对话浮窗。

#### 方案 B｜直接替换

- 右下角主按钮改为“问 Lumino”；
- 计算器等工具作为浮窗中的快捷入口；
- 适合后续将服务顾问作为官网主要转化入口时使用。

首页首屏可增加一个非悬浮文字入口：

> 不确定需要哪项服务？问 Lumino

该入口与右下角按钮打开同一个浮窗，不创建第二套状态。

### 4.2 桌面端

- 浮窗固定于右下角，宽度建议 380–420px；
- 高度根据视口限制在 520–680px，内容区内部滚动；
- 默认只显示入口按钮；
- 展开后包含标题、边界说明、消息区、预选项和输入区；
- 不使用全屏遮罩，不阻断页面其他内容；
- 用户可继续浏览服务页，浮窗保留当前会话状态。

### 4.3 移动端

- 使用贴近底部的页面面板，而不是缩小桌面浮窗；
- 最大高度不超过可视区域，避开浏览器安全区和软键盘；
- 输入框始终可见；
- 预选项横向换行，不使用只能横向滑动才能发现的关键选项；
- 打开时将焦点移入面板，关闭后返回入口按钮。

### 4.4 视觉方向

遵循 Marketing v3：浅色工作界面、深绿主色、白色表面、1px 边线、6–8px 圆角，不增加头像、发光效果、渐变文字、聊天气泡表演或夸张阴影。

Agent 标题使用“Lumino 服务顾问”，状态文字使用“初步判断”或“正在查找已发布资料”，不使用“AI 正在深度思考”等拟人化文案。

固定组成：

1. 标题与关闭按钮；
2. 简短边界说明；
3. 对话记录；
4. 当前问题的预选回答；
5. 自由输入框；
6. 发送、停止生成和重新开始；
7. 来源、服务推荐与联系动作。

## 6. 用户输入方式

### 6.1 预选话题

初始状态展示六个入口：

1. 我的产品是否可能涉及 CBAM？
2. 进口商让我准备碳数据，应该从哪里开始？
3. CBAM 和产品碳足迹有什么区别？
4. 客户要求 ESG、碳盘查或 Scope 1/2/3
5. 想规划绿电、绿证或可再生能源证明
6. 不确定需要哪项服务

第二层根据上下文展示 2–5 个预选回答，例如：

- 钢铁；
- 铝；
- 其他产品；
- 我不确定产品分类。

预选项只是加速输入，不阻止用户自由回答。

### 6.2 自由输入

- 单次输入建议限制在 800 个汉字或 2,000 个字符以内；
- 支持中文和英文；
- Enter 发送，Shift+Enter 换行；
- 发送前去除首尾空格；
- 禁止空消息和连续重复提交；
- 网络失败时保留原输入并提供重试；
- 用户输入个人信息或生产资料时，提示不要在浮窗继续提交，并引导至受控联系渠道。

## 7. 打印式输出

### 7.1 输出方式

模型回答使用流式响应，固定答案直接从本地结构化登记读取。显示效果采用**逐段或短语块输出**，而不是刻意缓慢的逐字动画：

- 文本到达后按短语或 8–20 个字符一批显示；
- 标题、正文、来源和 CTA 按顺序出现；
- 用户可点击“显示完整回答”跳过动画；
- 用户开始新的输入时立即完成上一条回答；
- 生成期间显示“停止”按钮；
- 连接中断时保留已经显示的内容，并提供“继续/重试”。

### 7.2 可访问性

- `prefers-reduced-motion: reduce` 下直接显示完整文本；
- 屏幕阅读器不逐字播报，只在一个完整段落完成后通过 `aria-live="polite"` 宣布；
- 流式光标不得成为唯一的加载指示；
- 所有预选项、来源和 CTA 均可通过键盘访问；
- Escape 关闭浮窗，关闭后焦点回到入口按钮；
- 不使用自动滚动抢夺用户正在阅读的位置；只有用户停留在消息底部时才跟随新内容。

## 8. 对话模式

采用“确定性分诊 + 固定答案 + 工具路由 + 检索问答 + 服务推荐”的分层模式。

### 8.1 请求路由顺序

每次输入按以下顺序处理，命中后即停止向下执行：

1. 预选话题或确定性意图规则；
2. 现有工具或已发布页面路由；
3. 已审核固定答案；
4. 结构化服务分诊；
5. 已发布知识检索 + 模型解释；
6. 无可靠依据时停止并转联系入口。

前四层均可在模型不可用、API 超时或预算用尽时正常运行。

### 8.2 固定答案登记

固定答案使用受版本控制的结构化登记，不散落硬编码在 UI 中。每条至少包含：

```text
answerId
intent
language
title
answer
suggestedReplies
links
serviceMatches
sourceIds
reviewedAt
reviewer
status
version
```

只允许使用 `status=published` 且在审查周期内的答案。法规性固定答案仍必须展示来源，不因“未调用模型”而降低审核要求。

### 8.3 CN Code 意图的工具路由

用户询问查找、确认或试算 CN Code 时，默认不调用模型猜测编码，而是返回固定边界说明和以下入口：

- `进入 CBAM 试算器` → `/calculator`，用于从已支持的 CN Code 列表中选择产品并进行成本试算；
- `查看 HS / CN / TARIC 核对指南` → `/knowledge/article?id=cbam-hs-cn-codes`；
- `需要归类复核` → CBAM 服务页或联系页。

当前试算器是“在已支持列表中选择 CN Code”，不宣称根据产品描述自动完成海关归类。后续可让试算器接收经验证的 `cnCode`、`year` 等非敏感 URL 参数，但非法或未支持编码必须回到手动选择状态。

### 8.4 标准流程

```text
预选话题或自由输入
        ↓
确定性意图识别
        ↓
固定答案 / 工具路由是否命中？
   │是                     │否
   ↓                       ↓
直接回答或跳转       检索结构化服务事实和已发布知识
                           ↓
                       必要时调用模型
        ↓
回答当前问题
        ↓
一次询问一个缺失事实（最多 3 个）
        ↓
推荐 1 个主服务，必要时附 1 个关联服务
        ↓
服务页 / 知识文章 / 联系入口
```

### 8.5 回答格式

每次回答优先采用以下顺序：

1. **初步判断**：直接回答；
2. **为什么**：1–3 个关键理由；
3. **还需要确认**：只问一个问题；
4. **下一步**：预选回答或相关页面；
5. **来源**：法规性、方法性问题显示来源。

单次回答建议控制在 150–300 个汉字。复杂问题先给短结论，再允许用户选择“展开说明”。

### 8.6 会话限制

- 默认最多连续 8 轮；
- 第 6 轮开始允许主动总结；
- 第 8 轮给出服务建议和下一步，不继续无限追问；
- 用户切换完全不同的话题时，询问是否重新开始；
- 不把早期未确认信息自动当成正式事实。

## 9. 预选话题与服务映射

| 话题 | 主服务 | 关键确认问题 | 推荐输出 |
|---|---|---|---|
| 产品是否涉及 CBAM | CBAM | 产品、目标市场、HS/CN 编码、进口商要求 | 适用性初筛、需核对字段、CBAM 服务页 |
| 进口商需要哪些数据 | CBAM | 产品、厂区、前体、提交期限 | 资料清单、相关文章、联系入口 |
| 默认值还是实际值 | CBAM | 产品、数据完整度、供应商资料 | 两种路径区别和切换条件 |
| CBAM 与 PCF 的区别 | CBAM + PCF | 使用对象、模板、系统边界 | 主次服务建议和差异表 |
| 客户要求产品碳足迹 | PCF | 产品、功能单位、客户模板、系统边界 | PCF 准备清单和服务页 |
| ESG 报告或评级问卷 | ESG | 披露对象、指定框架、主体范围 | 框架选择初筛和资料准备 |
| Scope 1/2/3 | 碳盘查 | 组织范围、使用目的、Scope 3 需求 | 盘查边界和资料清单 |
| 绿电或绿证 | 碳资产与绿证 | 年用电、目标比例、接受凭证 | 路径初筛和证明材料 |
| PPWR/EUDR/市场准入 | 出口合规 | 目标市场、产品、紧急要求 | 适用专题与出口合规入口 |
| 不确定需要什么 | 服务分诊 | 谁提出要求、要求的交付物、截止时间 | 1 个主服务 + 最多 1 个关联服务 |

## 10. 模型策略

### 10.1 默认模型

建议使用 `gpt-6-luna`，推理强度采用 `low` 或 `medium`。

适用原因：

- 对话任务范围明确；
- 高频调用需要控制延迟和成本；
- 主要工作是意图识别、资料检索、简短解释和服务分诊；
- 正确性主要来自受控知识库和输出规则，而不是依赖模型自由推理。

官方模型选择指南将 Luna 定位为适合范围明确的任务、分诊和高频自动化：
<https://developers.openai.com/api/docs/guides/model-selection>

### 10.2 条件升级模型

以下情况可升级到 `gpt-6.1-sol`，推理强度建议 `medium`：

- 同时涉及两项以上服务；
- 用户描述较长或前后冲突；
- 需要比较 CBAM、PCF、ESG 和碳盘查的边界；
- 检索结果来自多个规则来源；
- 默认模型返回低置信度或无法稳定生成服务建议。

不建议每一轮都使用高能力模型，也不建议第一版默认使用 Astra。

### 10.3 不建议微调

第一版不进行模型微调。知识更新应通过结构化服务目录和检索库完成。只有积累足够多、已脱敏且经人工标注的真实对话后，才评估是否为语气、分类或结构稳定性进行微调。

## 11. 知识库结构

采用“结构化事实 + 已发布知识 + 人工审核官方依据”三层结构。

### 11.1 第一层：结构化服务事实

权威来源：

- `apps/site/site/services-catalog.js`；
- `docs/public-claims-register.md`；
- 公开联系信息；
- 隐私、Cookie 和用户内容许可文件。

这一层控制：

- 服务名称；
- 适用对象；
- 触发场景；
- 所需资料；
- 工作步骤；
- 交付物；
- 服务边界；
- 推荐入口。

服务推荐应优先由确定性规则和结构化字段完成，不依赖向量检索猜测。

### 11.2 第二层：已发布知识文章

来源：`apps/site/knowledge/catalog.json` 中 `status=published` 的文章及对应正文。

第一版重点覆盖：

- CBAM 进口商数据要求；
- HS/CN/TARIC；
- 默认值与实际值；
- 前体材料；
- 申报节奏；
- CBAM 与 PCF 区别；
- PCF 系统边界、活动数据和热点；
- Scope 1/2/3 与首年碳盘查；
- ESG 框架选择；
- PPWR、EUDR 等出口合规专题。

### 11.3 第三层：人工审核的官方依据

逐步加入：

- 欧盟 CBAM 法规和实施规则摘要；
- 欧委会官方指南及模板说明；
- ISO、GHG Protocol 等可合法使用的摘要；
- PPWR、EUDR 等官方规则摘要；
- Lumino 已确认的适用日期、解释和边界。

不得上传无权复制的标准全文。

### 11.4 元数据

每份检索材料至少包含：

```text
documentId
title
serviceId
topic
jurisdiction
language
sourceType
sourceUrl
effectiveDate
reviewedAt
reviewer
status
version
```

检索时只允许使用 `status=published` 且在有效审查周期内的内容。

### 11.5 不进入知识库的内容

- 未发布文章和草稿；
- 内部服务成熟度标签；
- 客户生产数据、联系方式和历史咨询；
- Portal 内部演示状态；
- 无法核实的销售话术；
- 未授权客户案例；
- 未确认来源、日期或适用范围的法规内容。

### 11.6 检索方案

第二、第三层可以使用 Responses API 的 File Search 和 Vector Store，通过语义与关键词检索并按元数据过滤：
<https://developers.openai.com/api/docs/guides/tools-file-search>

建议每轮返回 3–5 个高相关片段；法规问题优先过滤 `sourceType=official`，服务问题优先读取结构化服务事实。

## 12. Agent 输出协议

使用 Structured Outputs，前端不直接解析自由文本。建议响应结构：

```json
{
  "intent": "cbam_scope",
  "answer_mode": "fixed",
  "answer": "初步判断文本",
  "confidence": "medium",
  "service_matches": [
    {
      "service_id": "cbam",
      "reason": "用户提到欧盟进口商和嵌入排放",
      "priority": 1
    }
  ],
  "next_question": "你的主要出口产品是什么？",
  "suggested_replies": ["钢铁", "铝", "其他", "不确定"],
  "sources": [
    {
      "title": "已发布文章或官方依据",
      "url": "/apps/site/knowledge/……"
    }
  ],
  "cta": {
    "type": "service",
    "label": "查看 CBAM 服务",
    "url": "/apps/site/services/cbam/"
  },
  "handoff": "none"
}
```

字段约束：

- `intent` 使用固定枚举；
- `answer_mode` 只能为 `fixed`、`tool_route`、`retrieval_model` 或 `fallback`；
- `confidence` 只能为 `high`、`medium`、`low`；
- `service_matches` 最多两个；
- `suggested_replies` 最多五个；
- `sources` 最多三个；
- `handoff` 只能为 `none`、`contact`、`expert_required`；
- 低置信度时不得输出确定性法规结论。

Structured Outputs 文档：
<https://developers.openai.com/api/docs/guides/structured-outputs>

## 13. 系统行为与安全边界

系统提示词必须包含以下规则：

1. 只使用检索到的已发布资料和结构化服务事实；
2. 不把模型自身知识当成当前法规依据；
3. 不编造来源、条款、日期、案例、客户、效果或价格；
4. 不输出内部 `PILOT`、`PLANNED` 等成熟度标签；
5. 不承诺认证、核查通过、进口商接受或监管认可；
6. 不提供正式法律意见；
7. 不根据有限描述直接确定 CN 编码适用性；
8. 不要求用户在聊天中提交账单、BOM、身份证件、联系方式或敏感生产数据；
9. 无依据时说明不能确认，并推荐人工咨询；
10. 每次只提出一个后续问题；
11. 回答保持简洁，避免连续长篇法规解释；
12. 推荐服务时说明原因，不进行强制销售。

还应配置：

- 单 IP/会话请求频率限制；
- 输入与输出安全审核；
- 提示注入检测和检索内容隔离；
- 服务端 API Key；
- 超时、重试和熔断；
- 最大输入、输出和轮次限制；
- 结构化日志，但不记录不必要的对话正文和个人信息。

## 14. 隐私与留资

### 14.1 第一阶段

- 不在浮窗要求用户提供姓名、电话或邮箱；
- 不创建正式销售线索；
- 不把聊天记录发送至 Portal；
- 不在 URL 中携带完整问题、公司名称或个人信息；
- 联系页只传递非敏感枚举参数，例如：

```text
serviceId=cbam
source=homepage-advisor
topic=cbam-scope
```

- 用户主动输入个人信息时，不重复展示，并提醒使用联系页或公开邮箱；
- API 请求使用 `store:false`，不建立长期 Conversation；
- 浏览器仅保留当前标签页所需的临时状态，关闭或重置后清除。

OpenAI 官方说明中，Response 默认存在保存行为，可通过 `store:false` 关闭该响应存储；长期 Conversation 不适合当前无正式留资和保留规则的第一阶段：
<https://developers.openai.com/api/docs/guides/conversation-state>

### 14.2 第二阶段

数据库、隐私流程和处理责任确认后，才允许增加：

- “请顾问联系我”；
- 联系用途的独立说明和主动确认；
- 最小必要联系方式；
- 用户确认后的非敏感对话摘要；
- 正式回执、保存期限、删除机制和工作人员权限。

第二阶段启用前必须重新审核隐私页、Cookie/本地存储说明、公开声明登记和 `0001` 审计。

## 15. 技术架构

```text
右下角浮窗
   │
   ├─ 预选话题 / 自由输入
   │
   ▼
/api/advisor（服务端，无状态）
   │
   ├─ 输入校验、限流、安全审核
   ├─ 确定性意图与服务规则
   ├─ 固定答案登记
   ├─ 工具与页面路由登记
   ├─ 结构化服务目录
   ├─ File Search / Vector Store
   └─ 仅未命中前述规则时调用 Luna；必要时升级 Sol
   │
   ▼
Structured Output
   │
   ├─ 流式回答
   ├─ 预选回复
   ├─ 来源
   └─ 服务页 / 知识页 / 联系页 CTA
```

### 15.1 前端

建议新增独立模块，不把 Agent 逻辑写入首页 HTML：

```text
apps/site/site/advisor-widget.js
apps/site/site/advisor-widget.css
apps/site/site/advisor-topics.js
```

现有 `float-tools.js` 应改为统一入口或调用 Advisor，不保留两个互相遮挡的悬浮组件。

### 15.2 服务端

建议新增：

```text
api/advisor.js
api/_lib/advisor-policy.js
api/_lib/advisor-retrieval.js
api/_lib/advisor-schema.js
```

纯业务规则、固定答案、路由登记、Schema 和评测数据建议放在当前 monorepo 内的独立 `packages/advisor/`，不与企业 Portal 的 `packages/agent/` 共用运行时权限。两者可共享已发布服务事实，但公开顾问不得获得 Portal 资产或正式写入能力。

API Key 只能存在服务端环境变量中，禁止在浏览器端直接调用模型。

### 15.3 对话状态

第一版使用无状态请求：每轮携带经过裁剪的最近消息和结构化会话摘要。不要依赖长期服务端 Conversation。

建议保留：

- 最近 4–6 轮对话；
- 已确认的非敏感事实；
- 当前意图；
- 已推荐服务；
- 用户语言。

不保留：

- 用户主动输入的个人信息；
- 完整长期聊天记录；
- 客户上传资料；
- 未确认的推断事实。

## 16. 关键界面状态

| 状态 | 用户应看到的内容 |
|---|---|
| 收起 | 单一右下角入口，不遮挡页面关键 CTA |
| 初次展开 | 简短欢迎语、边界说明、六个预选话题和输入框 |
| 用户已选择 | 选择进入对话记录，显示一个后续问题 |
| 正在连接 | 明确的连接状态和取消入口 |
| 流式回答 | 短语块逐步出现，可显示完整回答或停止 |
| 检索无结果 | 明确无法确认，提供相关服务页或人工联系 |
| 网络失败 | 保留输入和已显示内容，提供重试 |
| 达到轮次限制 | 给出会话总结、推荐服务和下一步 |
| 敏感信息输入 | 不复述敏感值，提示停止提交并转到受控渠道 |
| 服务推荐 | 1 个主服务、最多 1 个关联服务、原因和 CTA |
| 关闭后重开 | 当前标签页内恢复；提供“重新开始” |

## 17. 内容与知识治理

### 17.1 发布流程

1. 内容负责人新增或修改服务/知识内容；
2. 业务负责人核对服务范围；
3. 法规或方法内容由指定审阅人确认；
4. 设置 `reviewedAt`、版本和状态；
5. 构建 Agent 知识包并更新 Vector Store；
6. 运行回归评测；
7. 通过后发布；
8. 失败时回滚到上一知识版本。

### 17.2 失效规则

- 超过审查周期的法规内容不用于确定性回答；
- 被撤回或更新的材料先从 Agent 可检索集合移除；
- Vector Store 删除具有最终一致性，应保留版本切换和发布等待窗口；
- 页面内容、Agent 知识和公开声明登记必须使用相同版本来源。

**完成标志**：交互体验通过，不依赖模型质量掩盖界面问题。

- 每周复核：指标 + 内部反馈表补齐高频无结果问题，经知识发布与 `advisor-eval` 回归；
- 不启用聊天内直接留资。
- 运维细则：`docs/advisor/public-beta.md`。

### 19.1 Git 与发布流程

- `lumino-official-website` 作为官网、Roadmap 和 Issue 的正式仓库；

- 紧急修复也先在独立分支完成，合并至 `main` 后必须回合到 `dev`。

### Phase 5｜正式留资（后续）

依赖正式数据库、身份权限、保存删除、通知和隐私流程完成后再规划。

## 20. 验收标准

### 20.1 功能

- 不公开内部成熟度；
- 不虚构法规、服务、案例、数据或价格；
- 法规性回答有来源；
- 无依据时不输出确定性结论；
- 不把演示记录表述为正式送达；
- 不要求用户提交敏感材料。

### 20.3 可访问性与响应式

- 390px、768px、1440px 无横向溢出；
- 键盘可完成打开、选择、输入、停止和关闭；
- 焦点进入和返回正确；

- `aria-live` 不逐字骚扰屏幕阅读器；
- `prefers-reduced-motion` 下无打印动画；
- 200% 缩放仍能完成主要操作。

### 20.4 工程与安全

- API Key 不进入前端；
- 未授权接口默认拒绝；
- 输入长度、轮次和请求频率受控；
- 模型输出经过 Schema 校验；
- 默认不长期保存对话；
- 固定答案和工具路由可在模型 API 不可用时正常工作；
- CN Code 意图不会让模型根据有限描述直接作出归类结论；
- 每次请求记录命中层级，可统计“无模型解决率”和“工具路由率”；
- 评测集进入持续回归；
- `git diff --check`、语法检查和现有测试全部通过。

## 21. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 模型根据记忆回答过时法规 | 只允许检索已发布资料；无来源即停止 |
| 推荐错误服务 | 确定性服务规则优先；最多推荐两个；低置信度转人工 |
| 用户误认为正式法律意见 | 固定边界说明；答案使用“初步判断”；禁止保证性措辞 |
| 用户输入个人或生产信息 | 输入提示、检测、不复述、转受控渠道 |
| 浮窗干扰首页 CTA | 与现有工具入口合并；不增加第二个悬浮按钮 |
| 打印动画拖慢阅读 | 短语块输出、可跳过、减少动态效果下立即完成 |
| 对话过长导致成本和上下文失控 | 8 轮限制、摘要、输出长度限制、模型分级 |
| 知识内容更新后旧版本仍被检索 | 版本化知识包、发布等待、回归测试和回滚 |
| 用户把 Agent 当作正式交付渠道 | 不接受文件；不生成正式编号；CTA 指向联系页 |
| 固定答案过期 | 与知识文章共用发布状态、审查日期、责任人和回归测试 |
| 工具链接失效或参数不受支持 | 路由登记进入自动测试；无效参数回到安全默认页 |
| 将试算器误解为正式 CN 归类工具 | 固定边界文案；只选择支持列表；需归类判断时转人工复核 |
