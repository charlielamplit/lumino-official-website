## 2. Anti-patterns 判定

**通过，但不是满分。** 官网没有霓虹深色 AI 风、渐变文字、玻璃卡片或无意义指标。识别度来自细线、高对比排版和文档感。问题是“六项服务”与“四步流程”都使用平均卡片网格，且平台页使用空占位图，会削弱专业完成度。

## 4. 详细问题

### P1 重大

#### [P1] 官网信息架构未与已转型的多服务门户对齐

- **位置**：`Lumino 官网.dc.html` 主导航和页脚
- **影响**：访客看不到建议中的“平台—工具—解决方案—知识库”主线，容易继续把 Lumino 理解为 CBAM 项目站。
- **建议**：重建首页主导航和对应内容区，保留登录与预约为行动入口。
- **建议命令**：`/shape` → `/clarify` → `/arrange`

#### [P1] 独立平台页与当前产品事实矛盾，并存在未完成占位符

- **位置**：`Lumino 平台.dc.html`
- **影响**：“当前专注 CBAM”与已上线的统一服务总览、PCF 试点和数据资产架构冲突；四个“待补截图”会让公开页看起来未完工。
- **建议**：将平台页重构为“全局门户 + 企业数据资产 + 独立服务频道 + 受控交付”全景，使用真实原型结构而非占位图。
- **建议命令**：`/shape` → `/arrange` → `/polish`

#### [P1] 平台页移动菜单缺少完整状态语义

- **位置**：`Lumino 平台.dc.html` 移动菜单按钮
- **类别**：Accessibility
- **影响**：辅助技术无法知道菜单当前展开与否。
- **WCAG**：4.1.2 Name, Role, Value
- **建议**：加入动态 `aria-label`、`aria-expanded` 和 `aria-controls`。
- **建议命令**：`/harden`

### P2 次要

#### [P2] 全站导航词汇不一致

- **位置**：首页、平台、指南、关于和联系页页头/页脚
- **影响**：用户在页面间切换时看到不同的信息架构，无法建立稳定心智模型。
- **建议**：先在首页和平台页建立新导航基线，下一轮抽取全站共享导航。
- **建议命令**：`/normalize` → `/extract`

#### [P2] 公开官网依赖运行时 CDN 编译

- **位置**：`support.js`
- **类别**：Performance / Resilience
- **影响**：首次访问依赖 unpkg 可达，并在浏览器中加载 Babel；中国网络环境下存在首屏失败风险。
- **建议**：迁移为构建时编译或自托管依赖。
- **建议命令**：`/optimize`

#### [P2] 官网市场页与 Portal 设计 token 分离

- **位置**：多个 `.dc.html` 内联样式
- **类别**：Theming / Maintainability
- **影响**：颜色、字号或间距调整需要同时修改多页，易产生漂移。
- **建议**：抽取 marketing token 与全局导航组件，再逐页迁移。
- **建议命令**：`/extract` → `/normalize`

## 5. 正向发现

- 首页只有一个 `h1`，具有 skip link、可见焦点和 reduced-motion 支持。
- 主文案已从 CBAM 专站转向“AI + 平台化服务”，整体品牌表达正确。
- 六项服务已区分“已开通 / 试点 / 即将上线 / 规划中”，未伪造未建成工作空间。
- 客户门户预览直接展示任务，而非泛化的软件仪表盘。
- 移动首屏按钮、文字与 Portal 预览的空间层级清晰。

## 6. 本轮执行顺序

1. 对齐首页导航和页脚信息架构；
2. 增加工具、行业解决方案、行业知识库与浮动试算入口；
3. 重构平台页的统一多服务表达，删除占位截图；
4. 修复平台页移动菜单 ARIA 状态；
5. 执行桌面、移动、键盘、语义与链接回归检查；
6. 另立性能和全站 token 抽取为下一轮工程任务。
